# QA 完了の定義（ship の成果物を足す・直したとき）

成果物 = その ship の専用 tool と、ダッシュボードのページ。

```
Q1 静的検査 ─ Q2 規則の網羅 ─ Q3 配線 ─ Q4 本物の Claude ─ Q5 本物の DB とページ ─ Q6 安全 ─ Q7 退行 ─ Q8 repo の制約
   └──────────── 機械で確かめる ────────────┘   └──────────── 実機で確かめる ────────────┘
```

| # | 合格の条件 | 確かめ方 |
|---|---|---|
| Q1 | 型検査・lint（独自ルールを含む）・plugin のテストが全部通る | `npm run typecheck`・`npm run lint`・`claude plugin test src` |
| Q2 | logic の規則ごとに、通す例と拒む例のテストがある | 規則とテストの対応を数える |
| Q3 | その ship のセッションにだけ成果物の tool が出て、呼ぶと fleet の DB のその文書に書く | plugin を丸ごと読み込むテスト（`hooks/register.test.ts`） |
| Q4 | 新しいセッションの Claude が、SKILL.md と tool の説明だけで小さな依頼を書き切る。拒否されても、返った文から自分で直せる | `claude -p` でその ship を起こし、DB を読む |
| Q5 | Q4 で書いた DB の中身が、publish したダッシュボードのページにスマホ幅で崩れずに出る（ライト・ダーク） | 本物の artifact をブラウザで開き、スクリーンショットを残す |
| Q6 | 生の ArtifactData ではその文書を書けない。ページは DB の文字列を HTML として解釈しない | 拒否を確かめ、`<img onerror>` を入れた値でページを開く |
| Q7 | ほかの ship のページと tool、ダッシュボードの一覧と「あなたの番」が前と同じく動く | 既存のテストと、ページを開いて確かめる |
| Q8 | prompt は front matter を除き 30 行以内。勝手に足した仕様は報告した | 行数を数え、報告を読み返す |

QA 完了 = 見つかった不具合を直したあと、Q1〜Q8 を通しでやり直して全部合格し、未解決の指摘が 0 件。
